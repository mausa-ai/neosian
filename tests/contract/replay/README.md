# Frozen v1 reference corpus

The 261 results in `expected.json` were captured from the Python **1.13.0**
implementation at `9835be7`, before its retirement. No expected result was
generated by the Rust implementation. `home/` is that reference's seeded
store, with a synthetic login and a fixed `/fixture/demo` source path.

The original differential cases cover CLI memory, operator/archive,
mailbox, six client hook formats, MCP stdio and HTTP sessions, and raw
wire requests. Each compares output plus changed and removed files.
Only timestamps, generated UUIDs and installation/temporary paths compare
by shape; the named fixture IDs stay exact. The general comparison rules
are preserved in `harness.py`. The file suite separately pins byte-exact
body preservation.

Version banners and documentation are checked against the current Cargo
version and shipped manifest elsewhere, because v2 deliberately changes
those surfaces. Explicit v2 additions to MCP discovery are covered by the
current MCP contract tests; retained calls continue to use this reference.
S2's optional `memory_search` handshake field and `search_memory` discovery
entry are excluded only from the v1 comparison, with full independent S2
contracts checking them. Frozen expectations and seeded data stay unchanged.
S5's additive `upkeep_review` and `upkeep_apply` discovery entries are likewise
excluded from the v1 comparison; independent current contracts cover their
approval, permissions, provenance, interruption and erasure behavior.

Do not regenerate these expectations from a candidate binary to make a
failure pass. A change requires an explicit compatibility decision and a
reviewed expected-result diff. State content is synthetic. The status
capture also contains the original machine's PATH executable location.
That case now supplies one private PATH command and maps the old
machine-specific location to its fixture role; the executable count,
order, basename and other status fields stay exact. Independent product
cases assert exact supplied PATHs and shadowing for zero, one and two
commands. The frozen expected.json bytes are unchanged.

Setup diagnostics add `installation` to status and `registrations` to its client
rows. Only these new fields are projected out; `test_setup_check.py` checks their
paths, storage/capture reports, secret handling and isolated MCP probe separately.

The `prune no match text` case adjusts its duration input for the age of the
oldest seeded turn, keeping its cutoff at least eleven hours before that turn.
The originally captured `12h` input eventually selects the fixed seed as it
ages. This preserves the original no-match scenario and still compares every
output and file change against the unchanged reference.

S6's optional `knowledge_policy` handshake and `knowledge` tool discovery are
projected out of this frozen comparison and tested independently. All original
fixture and expected-result bytes remain unchanged.

S7 projects out optional change-feed discovery and the three optional mailbox
reference inputs with their description paragraph. Its `.changes/` and
`.transactions/` files have independent physical recovery tests; all legacy
document/history bytes still compare against the frozen fixtures.

The read heat log (#407) under `heat/` is v2 derived state beside the store,
written by the MCP memory and knowledge tools and covered by `test_heat.py`; it
is projected out of the home snapshot, and every store byte still compares.
